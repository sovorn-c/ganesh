# System Limitations and Disclosures

This document details the boundaries, explicit non-claims, and architectural limitations of the Ganesh research assistant.

## Release Readiness and Qualification Disclosures

1. **A local qualify pass is not production-ready:** While Ganesh enforces rigorous automated verification, schema integrity, and qualification suites, passing local qualification suites verifies only local release criteria. It does not constitute remote CI verification, production readiness, or a certification of error-free autonomous performance.
2. **Full-access is not a sandbox:** The `full-access` execution mode runs commands within the host environment's execution context. It does not provide operating system sandboxing, hardware containerization, or virtualization boundaries. Users must never treat `full-access` as an isolation or security sandbox.

## Research Validity Disclosures

- **Scholarly Validity:** Ganesh enforces deterministic data integrity, provenance tracking, and policy constraints. However, schema validation and LLM agreement alone never establish scholarly validity or scientific correctness. Final peer review and intellectual conclusions belong exclusively to the human researcher.
- **Model Inaccuracies:** Language model outputs can contain hallucinations, synthetic quotes, or erroneous reasoning. All claims generated by specialist sessions must be verified against primary evidence sources.
